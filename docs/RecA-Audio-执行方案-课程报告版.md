# RecA → Audio：课程/组会报告执行方案

> 约束：8 周内出报告；200–1000 GPU·h（8 卡几天）；主攻**通用音频 + 音乐**。
> 上游思路见 [RecA-Audio-实验思路.md](RecA-Audio-实验思路.md)；本文只保留能落地的部分。

## 1. 报告的定位与核心论点

课程报告不需要 SOTA，需要一个**讲得清、证得住、图好看**的论点。建议把整篇压成一句话：

> **把 RecA 迁到音频生成，收益不取决于"方法对不对"，而取决于"理解编码器留了多少信息"——存在一条倒 U 曲线；在峰值点上，无标注的 RecA 能追平甚至超过同算力的 caption 微调。**

## 2. 两条路线（建议都做，A 为主）

| | Track A：受控小模型（主） | Track B：真实基座（佐证） |
|---|---|---|
| 目的 | 干净地扫编码器 × 压缩率，画出倒 U | 证明在真实模型上也有增益 |
| 模型 | 自建 DiT/flow-matching 音频生成器（~150M），条件 = 冻结编码器特征 | Audio-Omni（冻结 MLLM + 训 DiT）或 UniAudio 2.0 |
| 数据 | 200–300 h 音乐/音效 | 2–5 万条片段（LoRA / 只训生成头） |
| 预算 | 200–300 GPU·h | 150–300 GPU·h |
| 风险 | 低（完全可控） | 中（权重/显存/接口不确定） |

**为什么主路线要自建**：真实基座只能负担 1–2 次训练，编码器、压缩率、模板全纠缠在一起，画不出倒 U。小模型把变量锁死，曲线才可信。课程报告里"受控实验 + 一个真实模型验证"是标准且稳妥的打法。

**Track B 的取舍**：优先 Audio-Omni（2026-04 公开，冻结 MLLM、只训 DiT，算力最省，且原生支持音效/音乐/语音与编辑）；拿不到权重就换 UniAudio 2.0；都不行就只做 Track A，报告依然完整（把局限写清楚即可）。

## 3. 编码器候选（音乐/音效场景，这是全篇的关键自变量）

| 编码器 | 类型 | 预期信息量 | 备注 |
|---|---|---|---|
| **CLAP**（LAION-CLAP） | 全局 pooled 512-d | 极低 | 近乎 caption，预期最差；也是"下界"对照 |
| **BEATs / PANNs** | 事件级帧特征 | 中 | 音效强、音乐弱 |
| **MERT-95M / MusicFM** | 音乐帧级 | 中高 | **音乐场景的主力候选**，含音色/结构 |
| **Whisper-large-v3** | 语音帧级 | 中（对音乐偏弱） | **负对照**：预期在音乐上迁移差，正好说明"编码器与域要匹配" |
| **AudioMAE** | 声学重建型 | 极高 | 可能触发 copy shortcut，是"上界/危险端" |

这条"CLAP → BEATs → MERT → AudioMAE"的排序，就是倒 U 曲线的横轴。Whisper 作为跨域负对照，能让报告多一层论证。

压缩率：`{1500, 750, 375, 96}` tokens（帧池化 + 线性/Perceiver 压缩），共 4 档。

## 4. 数据（优先许可证干净、易获取）

| 用途 | 数据集 | 规模 | 许可 |
|---|---|---|---|
| 音乐训练 | MTG-Jamendo、FMA-small/medium | 100–300 h | CC |
| 音乐训练（多轨） | Slakh2100 | ~150 h | CC BY 4.0 |
| 音效训练 | FSD50K、VGGSound 子集 | 50–150 h | CC / 研究用途 |
| 评测（生成） | AudioCaps test、MusicCaps | 固定集 | 仅评测 |
| 评测（自建） | 200 条"细节导向"提示词（音色/空间/质感） | 手写 | — |

**自建提示词集是这份报告的关键资产**：RecA 的卖点是细粒度细节，而通用 benchmark 的 prompt 太粗（"a jazz song"），区分度低。写 200 条强调音色、混响、演奏法的 prompt（如 "brushed drums, upright bass, small warm room, vinyl crackle"），才能显出差异。

## 5. 实验清单

| # | 实验 | 设置 | GPU·h | 产出 |
|---|---|---|---|---|
| **E1** | 重建诊断 | 基座 + 自身特征重建 100 条，人工听 + 指标 | 10 | 图 1、Go/No-Go |
| **E2** | 表征探针 | 从各编码器特征线性预测：音色/乐器、节拍、响度、混响、语音性 | 15 | "哪些属性可恢复"热力图 |

| **E5** | 主对比 | best 编码器：Base / caption-SFT / RecA / RecA+T2A | 80 | 图 3 |
| **E6** | 模板消融 | 原生 token / "Repeat" / 空 / "Describe" | 24 | 捷径证据（定性即可） |
| **E7** | 泄漏诊断 | h-dropout ∈ {0, 0.1, 0.3}，测重建 SECS vs T2A | 30 | 图 4（可选） |
| **E8** | 真实基座 | Track B：1 次 RecA + 同预算对照 | 150–300 | 佐证表 |

## 6. 评测协议

| 维度 | 指标 | 注意 |
|---|---|---|
| 分布距离 | FAD（VGGish + CLAP + MERT 三套编码器） | 单套 FAD 不可信；固定参考集、3 seed、报 CI |
| 文本一致性 | CLAP score、AudioBox Aesthetics | 易饱和，配 hard prompts |
| 音乐结构 | beat F1、调性一致性 | 用 `beat_this` / `madmom` |
| 音效内容 | BEATs/PANNs 事件探针、事件时序 | 检 "该有的声音在不在、顺序对不对" |
| 重建保真 | mel-L1、SI-SDR、SECS（若含人声） | 直接对应 RecA 目标 |
| 人评 | 3 项 5 分制 A/B | 课程报告里最有说服力的一栏 |

**污染控制**：MusicCaps/AudioCaps 大概率在基座训练集里，只用于**相对**比较；主结论用自建 200 条 + 人评。

## 7. 八周排期

| 周 | 任务 | 里程碑 |
|---|---|---|
| W1 | 数据管线、特征预计算、E1 诊断、E2 探针 | 拿到图 1；确认 headroom |
| W2 | Toy 生成器 + 训练脚本，跑通 E3 | 基线能出声、FAD 合理 |
| W3 | E4 编码器扫描（12 次短训，特征已缓存，很快） | **图 2 初版** |
| W4 | E5 主对比 + E6 模板消融 | 图 3 |
| W5 | E7 泄漏诊断；补 seed；Track B 环境 | 图 4 / 真实基座跑通 |
| W6 | E8 真实基座；E9 人评 | 佐证表 + 主观分 |
| W7 | 图表精修、失败案例分析、写报告 | 初稿 |
| W8 | 组会 / 答辩 | 终稿 |

**关键路径**：W1 的 E1 决定后面做什么。如果 E1 显示基座重建已很好，立刻把 Track B 换成音乐编辑/修复场景（那里 headroom 更大）。

## 8. 报告结构（15 分钟 / 8 页）

1. 动机（1 页）：caption 太稀 → 音频更稀；一张"重建失败"的频谱图胜过千言。
2. 方法（1 页）：三行公式 + 与图像 RecA 的差异表。
3. 诊断（1 页）：图 1。
4. **主结果（2 页）**：图 2 倒 U + 图 3 对比。
5. 分析（1 页）：探针热力图 + 泄漏诊断。
6. 局限与展望（0.5 页）：只做通用音频、未做长音频、人评样本小。
7. 附录：模板、超参、失败样例。

## 9. 三种可能结果，都能写成报告

| 结果 | 现象 | 怎么写 |
|---|---|---|
| **A. 有增益且有倒 U** | 峰值处 RecA > caption SFT | 最理想，按上述结构写 |
| **B. 有倒 U 但增益小** | 重建变好，T2A 提升有限 | 论点改成"重建保真 ≠ 生成提升"，分析瓶颈位置，反而更深刻 |
| **C. 无倒 U（单调）** | 信息越多越好 / 越少越好 | 说明音频的"语义-声学"耦合与图像不同，讨论为什么 CLIP 式的瓶颈在音频不成立——同样是合格的科学结论 |

课程报告最忌讳"没跑出效果就没内容"。**把 E1 + E2 + E4 做成主菜，E5 做成配菜**，任何结果都有话说。

## 10. 风险与预案

| 风险 | 预案 |
|---|---|
| Audio-Omni 权重未公开 | 只用 Track A；或换 UniAudio 2.0；报告里注明 |
| 8 卡显存不够跑基座 | 只训 DiT/LoRA、5 s 片段、冻结 MLLM、梯度检查点 |
| FAD 方差吃掉增益 | 三套编码器 + 3 seed + 人评，主结论落在人评 |
| 训练不收敛 | 先过拟合 100 条样本验证管线，再上全量 |
| 时间不够 | 砍 E8、E7，保 E1/E2/E4/E5 |

---

## 11. 预算裁剪 / 加强

- **200 GPU·h 版**：只做 Track A 的 E1/E2/E3/E4 + E5（单编码器），砍真实基座与人评扩大。论点仍成立（"倒 U 存在"）。
- **1000 GPU·h 版**：加 Track B 两个基座、加长音频（30 s）、加音频修复/编辑子任务、人评扩到 30 人。

---

## 12. 下一步要先确认的三件事

1. Audio-Omni 权重是否已可下载（决定 Track B 是否存在）。
2. 8 张卡的具体型号与显存（决定 toy 模型能否上 30 s 片段）。
3. 数据落盘空间（300 h 音频 + 预计算特征，约 1–2 TB）。
